# Масиви, що е то? 

Почти всяка програма работи не с една или две стойности, а с **много стойности от един и същи вид**: оценките на всички ученици в класа, температурите за всеки ден от месеца, пикселите на снимка, буквите в една дума...

За да пишем какъвто и да е смислен софтуер, ни трябва начин да **групираме такива данни заедно** и да работим с тях като с едно цяло.

Нека видим защо това е толкова важно с един съвсем прост пример.

---

## Задачата

> **Искаме да намерим и запазим първите пет прости числа.**

Напомняне: *просто* е число, по-голямо от 1, което се дели без остатък само на 1 и на себе си. Първите пет прости числа са **2, 3, 5, 7 и 11**.

Да приемем, че вече имаме готова функция `is_prime(n)`, която връща `1` (истина), ако `n` е просто, и `0` (лъжа), ако не е:

```c
int is_prime(int n)
{
    if (n < 2)
        return 0;

    for (int d = 2; d * d <= n; ++d)
    {
        if (n % d == 0)
            return 0; // намерихме делител → не е просто
    }

    return 1; // няма делители → просто е
}
```


## Как бихме го направили със сегашните си знания?

Засега знаем само как да създаваме отделни променливи. Затова единственото, което можем да направим, е да си заделим **пет отделни променливи** и да ги попълним една по една:

```c
int main(void)
{
    int p1, p2, p3, p4, p5;   // пет отделни променливи за пет числа

    int i = 2;

    // търсим първото просто число, започвайки от 2
    for (; !is_prime(i); ++i);
    p1 = i++;   // запазваме го и продължаваме от следващото число

    // търсим второто просто число
    for (; !is_prime(i); ++i);
    p2 = i++;

    // търсим третото просто число
    for (; !is_prime(i); ++i);
    p3 = i++;

    // ... и така нататък за p4 и p5

    return 0;
}
```

> 💡 **Как работи `for (; !is_prime(i); ++i);`?**
> Това е цикъл без тяло (забележете `;` накрая). Той просто увеличава `i`, докато `i` не стане просто число. Когато цикълът спре, в `i` стои търсеното число.

### Какъв е проблемът?

Кодът *работи*, но е изключително неудобен:

- 🔁 **Много повторение.** Едни и същи два реда копираме отново и отново. Ако открием грешка в тях, трябва да я поправим на пет места.
- 📈 **Не се мащабира.** Ами ако поискаме първите **100** прости числа? Или **10 000**? Ще пишем ли `p1`, `p2`, ..., `p10000` на ръка?
- 🚫 **Не можем да ги обходим с цикъл.** Ако после искаме да отпечатаме всичките пет числа, пак трябва да напишем пет отделни `printf`-а. Няма как да кажем „дай ми *k*-тата променлива“.

Накратко: пишем много код, а ние **не обичаме да пишем много код!**

---

## Какво всъщност бихме искали?

Идеалният вариант би бил да имаме **една-единствена променлива**, която побира **няколко стойности**, и да можем да достъпваме всяка от тях **по пореден номер**.

Тогава цялата задача може да се реши с един-единствен цикъл:

```c
int main(void)
{
    <нещо> primes;   // ❓ една променлива, която побира 5 числа

    int counter = 0; // колко прости числа сме намерили досега

    for (int i = 2; counter < 5; ++i)
    {
        if (is_prime(i))
        {
            // запазваме i като просто число с номер counter
            ++counter;
        }
    }

    return 0;
}
```

Забележете разликата:

| Със сегашните знания | Това, което искаме |
|---|---|
| 5 отделни променливи | 1 променлива |
| Код, копиран 5 пъти | Един цикъл |
| Трудно се променя броят | Променяме само числото `5` |
| Не може да се обходи с цикъл | Достъп по номер (индекс) |

Остават ни два въпроса:

1. **Какво да напишем на мястото на `<нещо>`?**
2. **Как да кажем „сложи `i` на позиция номер `counter`“?**

---

## Отговорът: масив!

Точно за това служат **масивите**.

> 📦 **Масивът** е поредица от елементи **от един и същи тип**, разположени **един след друг в паметта**, които имат **едно общо име** и се достъпват **по индекс** (пореден номер).

Ето решението:

```c
#include <stdio.h>

int is_prime(int n); // дефинирана по-горе

int main(void)
{
    int primes[5];   // масив от 5 цели числа

    int counter = 0;

    for (int i = 2; counter < 5; ++i)
    {
        if (is_prime(i))
        {
            primes[counter] = i; // записваме i на позиция counter
            ++counter;
        }
    }

    // отпечатваме всички намерени числа — пак с един цикъл!
    for (int k = 0; k < 5; ++k)
    {
        printf("primes[%d] = %d\n", k, primes[k]);
    }

    return 0;
}
```

Резултат:

```
primes[0] = 2
primes[1] = 3
primes[2] = 5
primes[3] = 7
primes[4] = 11
```

Ето как изглежда масивът `primes` в паметта:

```
 индекс:    [0]   [1]   [2]   [3]   [4]
          +-----+-----+-----+-----+-----+
 primes:  |  2  |  3  |  5  |  7  | 11  |
          +-----+-----+-----+-----+-----+
```

> ⚠️ **Важно:** индексите в C започват от **0**, а не от 1! Масив с 5 елемента има индекси от `0` до `4`. Опитът да се достъпи `primes[5]` е **грешка** (недефинирано поведение), защото такъв елемент няма, и компилаторът **няма** да ви предупреди за нея.

---

## Обобщение

- Когато имаме **много стойности от един и същи тип**, отделните променливи бързо стават неудобни.
- **Масивът** ни позволява да ги съберем под **едно име** и да ги достъпваме чрез **индекс**: `име[индекс]`.
- Индексите започват от **0** и стигат до **размер − 1**.
- Благодарение на индексите можем да обхождаме масив с **цикъл**, вместо да пишем един и същи код многократно.

В следващите части ще разгледаме подробно как се декларират и инициализират масиви, какво се случва с тях в паметта и защо `sizeof` понякога ни лъже.

## Дефиниране и използване на масиви 🧱

Вече знаем *защо* са ни нужни масиви. Сега да видим **как** се дефинират, какви правила има за размера им и за какво трябва да внимаваме.

## Дефиниране на масив

Общият вид на дефиницията е:

```c
тип име[размер];
```

Тоест ни трябват три неща:

| Част | Какво е | Пример |
|---|---|---|
| **Тип** | Типът на *всеки* елемент. Всички елементи в един масив са от един и същи тип. | `int`, `char`, `double`, `float` ... |
| **Име** | Обикновено име на променлива, чрез което се обръщаме към масива. | `primes`, `grades`, `buffer` |
| **Размер** | Колко елемента ще побира масивът. Записва се в квадратни скоби `[ ]`. | `[5]`, `[100]`, `[SIZE]` |

Например:

```c
int    grades[30];      // 30 цели числа
double temps[31];       // 31 дробни числа
char   name[20];        // 20 символа
```

След като масивът е създаден, **размерът му не може да се променя**. Ако сме заделили 30 елемента, те си остават 30, докато масивът съществува.

### 🤯 Тук нещата стават интересни: размерът

Типът и името са лесни. Проблемите идват от **размера**, т.е. от това какво *може* да стои вътре в `[ ]`.

**C** е стар език, който почти не ни пази от грешки, а стандартът му се е променял с годините. Затова **различните компилатори приемат различни неща** като размер на масив. Ето двата най-често срещани случая.

## 🪟 Ако компилирате с MSVC (компилаторът на Microsoft Visual Studio)

Тук правилата за размера са **много строги**. Като размер може да се подава **само константа по време на компилация** (compile-time constant), т.е. стойност, която компилаторът знае още *преди* програмата да е стартирала:

- ✅ **целочислени литерали**, т.е. числа, написани директно в кода: `100`, `42`
- ✅ **макроси**, дефинирани с `#define`: `#define SIZE 100`
- ✅ **изрази**, съставени само от горните: `SIZE * 2`, `10 + 5`

Причината е безопасността. Както ще видим след малко, ако позволим на *променливи* да определят размера на масив, се появяват много неясни ситуации и трудни за откриване грешки.

Накратко, ако пишете на Visual Studio, можете да дефинирате масиви **само** така:

```c
#define SIZE 100

int main(void)
{
    int arr1[SIZE];        // ✅ макрос
    int arr2[100];         // ✅ литерал
    int arr3[SIZE * 2];    // ✅ израз от константи

    // Но НЕ можете:
    const int size = 100;
    int arr4[size];        // ❌ грешка при компилация!

    return 0;
}
```

> 🤔 **Защо `const int size = 100;` не става, след като е `const`?**
>
> В езика **C** ключовата дума `const` **не** прави променливата константа по време на компилация. Тя само означава „**тази променлива е само за четене**“. За компилатора `size` си остава *обикновена променлива* със собствено място в паметта, която просто не може да се променя. Затова не може да служи като размер на масив в MSVC.

> ⚠️ **Капан за начинаещи:** ако файлът ви завършва на `.cpp` вместо на `.c`, Visual Studio го компилира като **C++**, а не като C. В C++ `const int size = 100;` *е* константа по време на компилация и горният пример ще се компилира без проблем. Затова винаги проверявайте, че файловете ви са с разширение `.c`!

## 🐧 Ако компилирате с GCC или Clang

Тези компилатори следват стандарта на C, а от версия **C99** насам той позволява **масиви с променлива дължина** (на английски **Variable Length Arrays**, съкратено **VLA**). При тях размерът може да бъде **всяка целочислена стойност, известна по време на изпълнение** (runtime), включително обикновена променлива.

Тоест можете да дефинирате масив с каквато дължина пожелаете, стига да се побира в **стековата памет** на програмата (обикновено няколко мегабайта).

```c
#define SIZE 10        // макрос → константа по време на компилация

int main(void)
{
    const int a = 10;  // локална константа → валиден размер за VLA (C99+)
    int var = 10;      // обикновена променлива → също валиден размер за VLA (C99+)

    int arr1[a];       // VLA: размерът се определя по време на изпълнение
    int arr2[SIZE];    // обикновен масив: размерът е известен при компилация
    int arr3[10];      // обикновен масив: размерът е известен при компилация
    int arr4[var];     // VLA: размерът се определя по време на изпълнение

    return 0;
}
```

Забележете, че `arr1` също е **VLA**, въпреки че `a` е `const`. Причината е същата като при MSVC: в C `const` не означава „константа по време на компилация“.

Ето един по-полезен пример, при който потребителят сам избира размера:

```c
#include <stdio.h>

int main(void)
{
    int n;
    printf("Колко числа ще въведете? ");
    scanf("%d", &n);

    int numbers[n];    // VLA: размерът е такъв, какъвто потребителят е въвел

    for (int i = 0; i < n; ++i)
    {
        scanf("%d", &numbers[i]);
    }

    return 0;
}
```

> ⚠️ Този код **няма да се компилира с MSVC**!

### 📌 Ограничения на VLA

VLA са удобни, но имат правила, които трябва да помните:

- 🏠 **Само в блокова област на действие.** VLA може да съществува само вътре във функция или блок `{ ... }`. В **глобалната област на действие** (извън всички функции) VLA **не** са позволени. Там размерът трябва да е константа по време на компилация:

    ```c
    int n = 10;
    int global_arr[n];    // ❌ грешка: глобален масив с променлив размер

    int main(void)
    {
        int local_arr[n]; // ✅ позволено: в блокова област на действие
        return 0;
    }
    ```

- 🚫 **Не могат да се инициализират при дефиниция** (до стандарта C23):

    ```c
    int n = 5;
    int arr[n] = {0};     // ❌ грешка при компилация
    ```

- 🚫 **Не могат да бъдат `static`.** VLA винаги живее в стека и изчезва в края на блока, в който е дефиниран.

- ❗ **Размерът трябва да е положително число.** Ако е `0`, отрицателен или неинициализиран, поведението е **недефинирано**: програмата може да се срине, да работи „нормално“ или да прави странни неща. Компилаторът **няма** да ви предупреди!

- 💥 **Няма защита от препълване на стека.** Ако поискате твърде голям масив (например `int arr[n];` при `n = 100 000 000`), програмата просто ще се срине (*stack overflow*) и няма как да проверите това предварително.

- 📎 **VLA не е задължителен в стандарта.** От **C11** насам поддръжката на VLA е *по избор* за компилаторите. GCC и Clang ги поддържат, но MSVC (както видяхме) не ги поддържа.

## 📊 Сравнение

| Какво стои в `[ ]` | MSVC | GCC / Clang (C99+) | Глобално (всички) |
|---|:---:|:---:|:---:|
| Литерал: `[100]` | ✅ | ✅ | ✅ |
| Макрос: `[SIZE]` | ✅ | ✅ | ✅ |
| `const int`: `[size]` | ❌ | ✅ (VLA) | ❌ |
| Обикновена променлива: `[n]` | ❌ | ✅ (VLA) | ❌ |

## 📝 Обобщение

- Масив се дефинира с `тип име[размер];`. След създаването му размерът **не може** да се променя.
- **Константите по време на компилация** (литерали и `#define` макроси) работят **навсякъде** и с **всеки компилатор**.
- В C `const` означава „**само за четене**“, а **не** „константа по време на компилация“.
- **GCC и Clang** поддържат **VLA**, т.е. масиви с размер, определен по време на изпълнение. **MSVC** не ги поддържа.
- VLA са позволени **само вътре във функции**, не могат да се инициализират с `= {...}` и крият много опасности.

> 💡 **Съвет:** ако искате кодът ви да се компилира навсякъде и да е безопасен, използвайте **`#define` константи** за размера на масивите. Когато наистина ви трябва масив с размер, известен едва по време на изпълнение, по-добрият избор обикновено е **динамичната памет** (`malloc`), с която ще се запознаем по-нататък.
