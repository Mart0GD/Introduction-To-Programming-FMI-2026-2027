## Дефиниране и използване на масиви

Вече знаем *защо* са ни нужни масиви. Сега да видим **как** се дефинират и какви правила има за размера им.

## Дефиниране на масив

Общият вид на дефиницията е:

```c
тип име[размер];
```

Тоест ни трябват три неща:

| Част | Какво е | Пример |
|---|---|---|
| **Тип** | Типът на *всеки* елемент. Всички елементи в един масив са от един и същи тип. | `int`, `char`, `double`, `float` ... |
| **Име** | Обикновено име на променлива, чрез което се обръщаме към масива. | `primes`, `grades`, `buffer` |
| **Размер** | Колко елемента ще побира масивът. Записва се в квадратни скоби `[ ]`. | `[5]`, `[100]`, `[SIZE]` |

Например:

```c
int    grades[30];      // 30 цели числа
double temps[31];       // 31 дробни числа
char   name[20];        // 20 символа
```

След като масивът е създаден, **размерът му не може да се променя**. Ако сме заделили 30 елемента, те си остават 30, докато масивът съществува.

### Размерът!

Типът и името са лесни. Проблемите идват от **размера**, т.е. какво *може* да стои вътре в `[ ]`.

**C** е стар език, който почти не ни пази от грешки, а стандартът му се е променял с годините. Затова **различните компилатори приемат различни неща** като размер на масив. Ето двата най-често срещани случая.

---

## Ако компилирате с MSVC (компилаторът на Microsoft Visual Studio)

Тук правилата за размера са **много строги**. Като размер може да се подава **само константа по време на компилация** (compile-time constant), т.е. стойност, която компилаторът знае още *преди* програмата да е стартирала:

- **Целочислени литерали**, т.е. числа, написани директно в кода: `100`, `42`
- **Макроси**, дефинирани с `#define`: `#define SIZE 100`
- **Изрази**, съставени само от горните: `SIZE * 2`, `10 + 5`

Причината е безопасността. Както ще видим след малко, ако позволим на *променливи* да определят размера на масив, се появяват много неясни ситуации и трудни за откриване грешки.

Накратко, ако пишете на Visual Studio, можете да дефинирате масиви **само** така:

```c
#define SIZE 100

int main(void)
{
    int arr1[SIZE];        // макрос
    int arr2[100];         // литерал
    int arr3[SIZE * 2];    // израз от константи

    // Но НЕ можете:
    const int size = 100;
    int arr4[size];        // ❌ грешка при компилация!

    return 0;
}
```

> [!NOTE]
> **Защо `const int size = 100;` не става, след като е `const`?**
>
> В езика **C** ключовата дума `const` **не** прави променливата константа по време на компилация. Тя само означава „**тази променлива е само за четене**“. За компилатора `size` си остава *обикновена променлива* със собствено място в паметта, която просто не може да се променя. Затова не може да служи като размер на масив в MSVC.

> [!IMPORTANT]
> Ако файлът ви завършва на `.cpp` вместо на `.c`, Visual Studio го компилира като **C++**. В C++ `const int size = 100;` *е* константа по време на компилация и горният пример ще се компилира без проблем. Затова внимавайте дали файловете ви са с разширение `.c`!

## Ако компилирате с GCC или Clang

Тези компилатори следват стандарта на C, а от версия **C99** насам той позволява **масиви с променлива дължина** (на английски **Variable Length Arrays**, съкратено **VLA**). При тях размерът може да бъде **всяка целочислена стойност, известна по време на изпълнение** (runtime), включително обикновена променлива.

Тоест можете да дефинирате масив с каквато дължина пожелаете, стига да се побира в **стековата памет** на програмата.

```c
#define SIZE 10        // макрос → константа по време на компилация

int main(void)
{
    const int a = 10;  // локална константа → валиден размер за VLA (C99+)
    int var = 10;      // обикновена променлива → също валиден размер за VLA (C99+)

    int arr1[a];       // VLA: размерът се определя по време на изпълнение
    int arr2[SIZE];    // обикновен масив: размерът е известен при компилация
    int arr3[10];      // обикновен масив: размерът е известен при компилация
    int arr4[var];     // VLA: размерът се определя по време на изпълнение

    return 0;
}
```

Забележете, че `arr1` също е **VLA**, въпреки че `a` е `const`. Причината е същата като при MSVC: в C `const` не означава „константа по време на компилация“.

Ето един по-полезен пример, при който потребителят сам избира размера:

```c
#include <stdio.h>

int main(void)
{
    int n;
    printf("Колко числа ще въведете? ");
    scanf("%d", &n);

    int numbers[n];    // VLA: размерът е такъв, какъвто потребителят е въвел

    for (int i = 0; i < n; ++i)
    {
        scanf("%d", &numbers[i]);
    }

    return 0;
}
```

> ⚠️ Този код **няма да се компилира с MSVC**!

### Ограничения на VLA

VLA са удобни, но имат правила, които трябва да помните:

- **Само в блокова област на действие.** VLA може да съществува само вътре във функция или блок `{ ... }`. В **глобалната област на действие** (извън всички функции) VLA **не** са позволени. Там размерът трябва да е константа по време на компилация:

    ```c
    int n = 10;
    int global_arr[n];    // ❌ грешка: глобален масив с променлив размер

    int main(void)
    {
        int local_arr[n]; // ✅ позволено: в блокова област на действие
        return 0;
    }
    ```

- **Не могат да се инициализират при дефиниция** (до стандарта C23):

    ```c
    int n = 5;
    int arr[n] = {0};     // ❌ грешка при компилация
    ```

- **Не могат да бъдат `static`.** VLA винаги живее в стека и изчезва в края на блока, в който е дефиниран.

- ❗ **Размерът трябва да е положително число.** Ако е `0`, отрицателен или неинициализиран, поведението е **недефинирано**: програмата може да се срине, да работи „нормално“ или да прави странни неща. Компилаторът **няма** да ви предупреди!

- **Няма защита от препълване на стека.** Ако поискате твърде голям масив (например `int arr[n];` при `n = 100 000 000`), програмата просто ще се срине (*stack overflow*) и няма как да проверите това предварително.

- **VLA не е задължителен в стандарта.** От **C11** насам поддръжката на VLA е *по избор* за компилаторите. GCC и Clang ги поддържат, но MSVC (както видяхме) не ги поддържа.

## Сравнение

| Какво стои в `[ ]` | MSVC | GCC / Clang (C99+) | Глобално (всички) |
|---|:---:|:---:|:---:|
| Литерал: `[100]` | ✅ | ✅ | ✅ |
| Макрос: `[SIZE]` | ✅ | ✅ | ✅ |
| `const int`: `[size]` | ❌ | ✅ (VLA) | ❌ |
| Обикновена променлива: `[n]` | ❌ | ✅ (VLA) | ❌ |

## 📝 Обобщение

- Масив се дефинира с `тип име[размер];`. След създаването му размерът **не може** да се променя.
- **Константите по време на компилация** (литерали и `#define` макроси) работят **навсякъде** и с **всеки компилатор**.
- В C `const` означава „**само за четене**“, а **не** „константа по време на компилация“.
- **GCC и Clang** поддържат **VLA**, т.е. масиви с размер, определен по време на изпълнение. **MSVC** не ги поддържа.
- VLA са позволени **само вътре във функции**, не могат да се инициализират с `= {...}` и крият много опасности.

> **Съвет:** ако искате кодът ви да се компилира навсякъде и да е безопасен, използвайте **`#define` константи** за размера на масивите. Когато наистина ви трябва масив с размер, известен едва по време на изпълнение, по-добрият избор обикновено е **динамичната памет** (`malloc`), с която ще се запознаем по-нататък.
