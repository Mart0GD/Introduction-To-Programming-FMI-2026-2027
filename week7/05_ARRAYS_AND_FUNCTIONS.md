# Работа с масиви и функции

Когато подаваме масив като аргумент на функция в **C**, освен самия масив трябва да подадем и неговия **размер**:

```c
// Подаваме масива заедно с размера му
void foo(int arr[], int size);

// Еквивалентен запис
void foo(int *arr, int size);
```

И двата записа дефинират **една и съща** функция. Параметърът `arr` и в двата случая е от тип `int *`, т.е. **указател към първия елемент** на масива.

> [!WARNING]
> Записът с квадратни скоби `[]` в параметрите на функция е **само за удобство** на програмиста. Компилаторът **автоматично преобразува** всеки параметър от тип „масив от `T`“ в „указател към `T`“.
>
> Това обяснява еквивалентността на записите от примера: `void foo(int arr[], int size);` е същото като `void foo(int *arr, int size);`.

## Какво се случва при извикване

При извикване на функцията името на масива се **разлага** (*array decay*) до указател към първия му елемент. Изразът `arr` в този контекст е еквивалентен на `&arr[0]`:

```c
int numbers[5] = {1, 2, 3, 4, 5};

foo(numbers, 5);       // на функцията се подава &numbers[0]
foo(&numbers[0], 5);   // абсолютно същото
```

Масивът **не се копира**. Копира се само **адресът** на първия му елемент. От това следват две важни последствия:

1. Функцията работи с **оригиналния масив** и всички промени по елементите му **се отразяват** извън нея. Това е подаване по адрес, разгледано в предходната тема.
2. Функцията **не получава информация за размера** на масива. Затова той трябва да се подаде отделно.

```c
void set_zero(int arr[], int size)
{
    for (int i = 0; i < size; ++i)
    {
        arr[i] = 0;   // променя оригиналния масив
    }
}

int main(void)
{
    int numbers[5] = {1, 2, 3, 4, 5};

    set_zero(numbers, 5);   // след извикването всички елементи на numbers са 0
    return 0;
}
```

> [!NOTE]
> Записът `arr[i]` работи и за указатели. За компилатора `arr[i]` означава `*(arr + i)`: „премести се с `i` елемента напред от адреса в `arr` и вземи стойността там“.


## Размер в квадратните скоби

Често ще срещнете функции, при които в квадратните скоби на параметъра е записано число:

```c
void foo(int arr[32], int size);
```

Това число **по никакъв начин не задължава** размера на масива и служи **единствено като документация** за читателя. Компилаторът го **игнорира** и преобразува параметъра в `int *arr`.

```c
int small[3] = {1, 2, 3};

foo(small, 3);   // компилира се без грешка, въпреки че масивът има 3, а не 32 елемента
```

> [!NOTE]
> От стандарта **C99** е възможен записът `int arr[static 32]`. Той означава, че извикващият **гарантира**, че масивът има **поне** 32 елемента. Това не е проверка по време на изпълнение, но някои компилатори (GCC, Clang) издават предупреждение, ако при компилация се вижда, че подаденият масив е по-малък. MSVC не поддържа този запис.

## Подаване на масив само за четене

Ако функцията само **чете** данните от масива и не трябва да ги променя, параметърът се дефинира като **указател към константа**:

```c
void print_arr(const int arr[], int size)   // или: const int *arr
{
    for (int i = 0; i < size; ++i)
    {
        printf("%d ", arr[i]);   // четене
        // arr[i] = 0;           // грешка при компилация
    }
}
```

> [!IMPORTANT]
> `const int arr[]` е **указател към константа** (`const int *arr`), а **не** константен указател (`int *const arr`). Защитени са **елементите** на масива, а не самият указател.


## Може ли да не подаваме размера?

Размерът трябва да се подава **изрично**, защото функцията получава **само копие на адреса на първия елемент**. От този адрес няма как да се разбере колко елемента има масивът.

Нека разгледаме пример:

```c
#include <stdio.h>

void print_ptr(const int arr[5])
{
    // arr е указател (const int *), а не масив!
    // sizeof(arr)    - 8 байта (размерът на указателя на 64-битова система)
    // sizeof(arr[0]) - 4 байта (размерът на int)
    //
    // Резултатът винаги е 8 / 4 = 2, независимо от размера на масива!
    int size = sizeof(arr) / sizeof(arr[0]);

    // Отпечатва само първите два елемента
    for (int i = 0; i < size; ++i)
    {
        printf("%d ", arr[i]);
    }
    printf("\n");
}

void print_array_ptr(int (*arr)[5])
{
    // arr е указател към ЦЕЛИЯ масив от 5 елемента
    // sizeof(*arr)      - 20 байта (размерът на целия масив: 5 * 4)
    // sizeof((*arr)[0]) - 4 байта  (размерът на int)
    //
    // Резултатът е 20 / 4 = 5
    int size = sizeof(*arr) / sizeof((*arr)[0]);

    // Отпечатва всички елементи
    for (int i = 0; i < size; ++i)
    {
        printf("%d ", (*arr)[i]);
    }
    printf("\n");
}

int main(void)
{
    int arr[5] = {1, 2, 3, 4, 5};

    printf("Size: %zu\n", sizeof(arr) / sizeof(arr[0]));   // 5

    print_ptr(arr);          // 1 2
    print_array_ptr(&arr);   // 1 2 3 4 5

    return 0;
}
```

Резултат:

```
Size: 5
1 2
1 2 3 4 5
```

**Във функцията `print_ptr`** параметърът е обикновен указател към `int`. `sizeof(arr)` връща **размера на указателя**, а не на масива. Резултатът е грешен, и то **без грешка при компилация**. GCC и Clang издават само предупреждение (`-Wsizeof-array-argument`).

**Във функцията `print_array_ptr`** параметърът е **указател към масив от 5 елемента** (`int (*)[5]`). Типът му съдържа размера, затова `sizeof(*arr)` връща размера на целия масив. При извикването се подава `&arr`, т.е. адресът на **целия масив**, а не само на първия елемент.

> [!WARNING]
> Подходът с указател към масив **не решава проблема в общия случай**. Функцията `print_array_ptr` приема **единствено** масиви с **точно 5** елемента. Масив с 4 или 6 елемента е от **различен тип** и компилаторът ще издаде предупреждение или грешка. Затова на практика размерът почти винаги се подава като **отделен параметър**.

## Кога `sizeof` дава размера на масива?

`sizeof` връща размера на **целия масив** само когато изразът, към който е приложен, е от **тип масив**:

| Израз | Тип | `sizeof` дава |
|---|---|---|
| `arr` в областта, където е дефиниран | `int[5]` | размера на масива (20) |
| `*p`, където `p` е `int (*)[5]` | `int[5]` | размера на масива (20) |
| параметър `int arr[]` или `int arr[5]` | `int *` | размера на указателя (8) |
| указател `int *p` | `int *` | размера на указателя (8) |

> [!WARNING]
> Чрез `sizeof` можем да получим размера на масива **само там, където е дефиниран** (или чрез указател към целия масив). Щом масивът бъде подаден като `int *`, информацията за размера му **се губи безвъзвратно**.
>
> Това важи както за масивите на стека, така и за глобалните масиви. За **VLA** `sizeof` също работи в областта, където масивът е дефиниран, но стойността се изчислява **по време на изпълнение**.


## Обобщение

- В параметрите на функция `int arr[]`, `int arr[32]` и `int *arr` са **един и същи тип**: указател към `int`.
- При подаване масивът **не се копира**. Подава се адресът на първия му елемент, затова функцията може да **променя оригинала**.
- Числото в `[ ]` на параметъра е **само документация** и не ограничава размера.
- Ако функцията само чете масива, параметърът трябва да бъде `const int arr[]` (указател към константа).
- Функцията **не знае** размера на масива. `sizeof` върху параметъра връща размера на **указателя**.
- Указател към масив (`int (*)[N]`) запазва размера, но работи само за масиви с **точно N** елемента.
- Затова размерът на масива почти винаги се подава като **отделен параметър**.
